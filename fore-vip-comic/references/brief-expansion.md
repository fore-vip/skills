# 主题信息不足：最优剧情设计与确认

适用场合：用户给的主题只有一句话、一个词，或只有角色/情绪/领域中的一项，不足以直接写出「起点 → 转折 → 终点」的主题路线。**剧情设计是本 SKILL 的职责，不能用一串选项题把设计工作推回用户，也不能未确认就开画。**

## 一、先判信息够不够（强制前置）

用四个要素判定：**主体 / 场景 / 冲突（或转折点） / 情绪倾向**。

| 明确给出的要素数 | 走哪条路 |
|---|---|
| ≥ 3 项 | 信息充分：按 SKILL.md 第一步收集剩余参数，进第二步 |
| ≤ 2 项 | 信息不足：走本文件的提案分支 |

判定只认用户明确说出的内容，不把「我觉得他大概是……」算进去。**主体有歧义**（如"你的样子""我的故事""画个人"）按未给出计。

## 二、提取已有信号（先提取，再问）

用户给的每一个具体词都要进入提案，不得替换成自以为更好的词。

| 信号 | 从哪找 | 例子 |
|---|---|---|
| 主体 | 名词、代词、自称 | "你的样子" → 助手拟人；"我们团队" → 职场群像 |
| 领域 / 场景 | 行业词、场景词、动词 | "加班" → 职场；"讲讲大模型" → 科技科普 |
| 情绪倾向 | 形容词、标点、语气 | "太离谱了" → 吐槽；"讲清楚" → 科普 |
| 受众 | "给谁看" | 客户 / 同事 / 孩子 / 自己 |
| 硬约束 | 明确的数量、风格、禁区 | "三格""不要红色" |

## 三、用最小充分假设补全（核心）

只补让四格成立所必需的四项：**主体落定、场景落定、转折落定、收尾落定**。每条补全都标 `[假设N]`，便于用户按编号修改。不确定的关键选择不私自拍板，放进确认问题让用户选。

| 题材 | 默认主体 | 默认场景 | 默认转折 | 默认收尾 |
|---|---|---|---|---|
| 喜剧梗 | 被需求压着的普通从业者 | 办公桌 + 聊天窗 | 同一句式连问堆叠 | 一句话打回，冷收 |
| 科普问答 | 拟人化的知识对象 + 提问者 | 干净桌面或自然场景 | 反直觉真相揭晓 | 俏皮一句 |
| 吐槽日常 | 用户本人或通勤者 | 通勤 / 家庭 / 消费场景 | 小事逐级升级 | 自嘲和解 |
| 产品说明 | 目标用户 | 具体痛点物件 | 转折出现 | 克制主张（过禁用词） |
| 情感共鸣 | 亲近的人 | 日常空间 | 细微触动 | 留白不说破 |

三条纪律：

1. 不引入用户没提过的专有名词、品牌、数字。
2. 默认参数（钢笔淡彩 / 四格 2×2 / 口语吐槽）只在用户没给时用，且必须写进假设清单。
3. 涉及**身份、立场、受众**的假设（如"你的样子"指谁）必须用选项让用户选；其余假设用「采纳 / 改某条」一次性确认。

## 四、剧情提案模板（必须按此输出）

```markdown
【主题提案】<一句话主题>

你给的：主体=…；场景=…；情绪=…（没有就写"未给出"）

拟采用路线：<起点 → 转折 → 终点>

[假设1] …
[假设2] …

| 格 | 景别 | 场景状态 | 光线 | 情绪 | 台词草案 |
|---|---|---|---|---|---|
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |
| 4 | | | | | |

参数：画风… / 版式… / 调性…
```

台词草案遵守字数预算（答案 ≤16 字、问题 ≤13 字），必须回扣路线；四格照 `narrative-patterns.md`「提示词参照模板」填写即可——取值数量只作软提醒，不用数值阈值卡创意。

## 五、确认闸门（强制，不可跳过）

1. 输出提案后**停下等待用户确认**。未确认前不得写 `storyboard.json`、不得编译、不得生图、不得报成本开跑。
2. 确认必须走 `AskUserQuestion`，选项固定三档：
   - 采纳提案，开始制作（推荐）
   - 改某条假设（用户注明编号，如"改假设1：画用户本人"）
   - 换一条主题路线（附一条替代路线供选）
3. 用户改假设 → 只重推受影响的格与台词，其余不动，重新出提案确认；不整份推倒。
4. 用户答「你定 / 随意」→ 视为采纳全部假设，直接进第二步，但必须把已采纳的假设清单留痕输出一次。
5. 提案不是交付物。确认后把路线、四维标注与台词草案落成 `storyboard.json`，再进编译器。

## 六、反模式（一律不允许）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| 空泛追问"请补充更多信息" | 把设计责任推回用户 | 先给提案，让用户改 |
| 用四个选项问"主题/场景/冲突是什么" | 剧情设计是本 SKILL 的职责 | 选项只用于参数和关键立场 |
| 不标假设直接开画 | 用户发现不对只能整组重做 | 假设编号，改一条即可 |
| 提案里四格是四个并列瞬间 | 违反主题路线与画面演进 | 按四维递进表写 |
| 用户沉默就当默认确认 | 没有确认就是没有确认 | 必须明确收到确认 |

## 七、已落地实例：用户只说"以你的样子做为主题"

**判定**：主体有歧义（"你"指谁？），场景/冲突/情绪均未给出 → 明确要素 1 项 < 3 → 走提案分支。

**提取到的信号**：主体="你"（歧义，需确认）；其余未给出；无硬约束。

**提案（确认前输出）**：

```markdown
【主题提案】把洞察助手拟人成分析师，讲"从信息过载到一句结论"

你给的：主体="你"（有歧义）；场景=未给出；情绪=未给出

拟采用路线：混沌待理 → 四路加压 → 聚焦洞察 → 归位收束

[假设1] "你"指 fore.vip 洞察助手的拟人形象，不是用户本人
[假设2] 场景是办公桌前整理竞品与社区信息
[假设3] 冲突是四路材料同时压过来，靠放大关键处破局
[假设4] 情绪克制专业，收尾释然
[假设5] 参数用钢笔淡彩 / 四格 2×2 / 正式克制

| 格 | 景别 | 场景状态 | 光线 | 情绪 | 台词草案 |
|---|---|---|---|---|---|
| 1 | wide | cluttered | soft | 困惑 | 需求来了，先看清全貌。 |
| 2 | overhead | piled | warm | 加压 | 四路材料，同时压过来。 |
| 3 | extreme_close | focused | highlight | 决断 | 关键处，只需放大一处。 |
| 4 | wide | settled | clear | 释然 | 结论一句，事情就清楚了。 |

参数：钢笔淡彩 / 四格 2×2 / 正式克制
```

**确认问题**：采纳提案，开始制作 / 改假设1（改成用户本人）/ 换一条主题路线（如喜剧吐槽路线）。

确认后才写 `storyboard.json`。本实例同时说明：直接问画风、版式、调性三项参数却自拟主题开画，是信息不足场景下最典型的失败流程。
