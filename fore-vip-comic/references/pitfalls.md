# 踩坑与能力边界

## 一、生图纪律（违反会直接烧钱）

1. **逐张串行调用 ImageGen，且每张指定互不相同的 `output_dir`。**
   输出文件名按**秒级时间戳**生成，并行调用会撞名互相覆盖。实测：并行发 4 张，只落盘 3 个文件，缺失的一格必须重新生成，白花 5-10 credits。
2. **开跑前告知用户成本**：每张约 5-10 credits，说明总张数与预估额度（该工具要求成本前置告知）。
3. **生图输出的右下角自带 `AI生成` 水印**，合成时 `crop_bottom: 100`（1536×1024 原图）即可清除；裁得不够会残留，裁得过多会切到画面，100px 是实测值。
4. 单格尺寸用 `1536x1024` + `quality: high`；小于 1024 宽时中文气泡与画面细节都会吃力。

## 二、能力边界：这些画不出来

| 类型 | 表现 | 对策 |
|---|---|---|
| 中文文字、数字 | 必错字、必乱码 | 一律程序叠加，prompt 里明确 `NO text/letters/numbers` |
| **瞬时动态** | "手指正触碰叶片、叶片已经合拢"连续两次失败：一次缺动作、沦为植物图鉴；一次比例失衡 | **换静态但形态特征强的主体**（改画蒲公英绒球+飘散种子，一次成功） |
| 精确的多物体空间关系 | "手指与叶片的相对位置"不可控 | 拆解为单主体特写，或改用动作后状态 |
| 无意义装饰 | 自作主张加红方块、印章、乱码 | 合成时修补（见下），或在 prompt 里点名禁止 |

**判据：同一格两次生成不达标，不要第三次硬拗。** 改主体或换表达角度，生图按张计费，试错成本高于改脚本。

## 三、修补 AI 瑕疵

1. **先扫像素拿精确 bbox，不要肉眼估。** 实测肉眼估 `(1020, 6)`，真实位置是 `(1463, 28)`，差了 400+ px，白跑一轮。
2. 从邻近干净区域 `crop` 一块 `paste` 覆盖（`panels[].patches`）。
3. **重新扫描确认残留为 0 再交付**：

```python
residual = sum(1 for y in range(0, 130) for x in range(1400, W)
               if im.getpixel((x, y))[0] > 150 and im.getpixel((x, y))[1] < 95)
print("residual red px:", residual)
```

## 四、合成阶段的两个必守校验

脚本已内置，但改脚本时要保留：

1. **文字块宽度**：椭圆内可用高度 = `2*ry*sqrt(1-(block_w/(2*rx))²)`，必须 > 文字块总高。
   实测：16 字 × 48px = 768px 的答案行，在 `rx=440` 下只剩 101px 可用高（需 108px）→ 断言当场拦下，改 `rx=470` 后余量升到 156px。
2. **尾巴基点必须在气泡主体内部**（椭圆用 `(dx/rx)²+(dy/ry)² < 1`），否则三角形底边外露穿帮。

## 五、环境事实（macOS，实测）

- 中文字体：`/System/Library/Fonts/Hiragino Sans GB.ttc`（冬青黑体，漫画对白观感最正），宋体 `/System/Library/Fonts/Supplemental/Songti.ttc` 备选。
- **macOS 默认不装手写体**（Hannotate、楷体系需在字体册手动下载），不要假设存在。
- `.ttc` 内含多个字面，用像素密度探测自动挑最粗（渲染探针 → 灰度直方图取暗像素最多者）。
- Pillow 12.x：`Image.getdata()` 已弃用，统计像素用 `histogram()`。
- 文字定位一律用 `anchor`（`"mm"` / `"lm"`）；注意 `ImageDraw.text` 的参数顺序是 **`(xy, text, ...)`**，写成 `(text, xy)` 会抛 `'tuple' object has no attribute 'split'`。

## 六、通用工作纪律

- 同一文件多次编辑**必须串行**；工具报错不等于没改（也可能已落盘），改完一律重读或 grep 复核。
- 复查批量改动用 `grep -rnE 'A|B'`（BSD grep 不支持 `\|` 交替，会静默 0 命中）。
