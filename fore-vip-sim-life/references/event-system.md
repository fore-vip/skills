# 事件系统 · 生成，而不是查表

## 一句话

**引擎掷槽位，模型写事件，引擎再校验。**

固定事件表的问题不在于条数少，而在于它只有作者想到的那几百种人生。真人一生的意外，绝大部分不在任何表里。但完全交给模型也不行——它会写出「他的人生迎来重大转折」这种没有信息的句子，而且会让穷人一路发财、让没结婚的人丧偶。

所以拆成两半：**「该发生什么类型的事」由脚本随机决定，「具体发生了什么」由模型即时生成，「这件事能不能成立」由脚本逐条验。**

## 一年一轮的三条命令

```bash
# ① 掷槽位：类别 / 方向 / 分量 / 约束 / 旧账
python3 life_engine.py brief --state <S> --kind work --action "去城里投奔表哥" --bonus 3

# ② 模型按 slot 写 event.json

# ③ 提交：校验通过才落地
python3 life_engine.py commit --state <S> --event event.json --status "在城中村落脚"
```

`brief` 不改属性，只把掷好的轮次上下文存进 `state.json` 的 `pending_turn`；`commit` 才会真正推进这一年。所以顺序不能反，也不能跳。

## 槽位从哪来（脚本负责的部分）

```
类别      9 类：谋生 / 钱 / 家里 / 感情 / 身体 / 人情 / 自己 / 时代 / 意外
  ↑ 按年龄区间、今年的行动类型、六维处境加权抽
方向      正 / 负 / 混合 / 中性
  ↑ 由今年掷骰结果决定倾向：大成功时正向 72%、负向 0；失败时负向 74%
分量      1–3 级
  ↑ 大成功/失败 → 2–3 级；老小两头压到 2 级以内
```

加权让「什么样的处境遇到什么样的事」成立：

- 健康低于 58 → 「身体」权重上升
- 财富低于 42 → 「钱」权重上升
- 这一年做的是 `work` → 「谋生」「钱」权重 ×3
- 声量高 → 「人情」权重上升
- 已婚 → 「感情」权重下降

于是同一个 40 岁样本，做工的人和养病的人，一年里遇到的类别分布明显不同；但**具体发生什么仍然每次都新**。

## 槽位里附带的五样东西

| 字段 | 作用 |
|---|---|
| `constraints` | 把「不能出现什么」写成人话：未婚不能有配偶、6 岁孩子不能抱孙、1985 年没有微信、非贫困家庭不挑水 |
| `open` | 往年 `then` 留下的未了结之事，带 pid 和最后期限 |
| `loose_ends` | 期限到了也没兑现的旧账，已经烂在过去了，但随时可以被翻出来 |
| `people` | `due` 是今年该回来的人，`roster` 是在册的全体，`note` 告诉你该添新人还是该收 |
| `echo` | 今年必须回响的那件旧事（见 `references/people-and-echo.md`） |
| `exemplars` | 同类旧事件 6 条，只给标题和钩子，作语感参照，**禁止照抄** |

`exemplars` 是这套设计里唯一保留固定库的地方——不是为了复用事件，而是为了让生成出来的句子保持同一种水位：小、具体、不解释意义。不读它，模型会往「跌宕起伏」上写。

## 校验拦什么（脚本负责的另一半）

| 层级 | 规则 |
|---|---|
| 结构 | title 3–20 字、hook 12–110 字、why 必填、effects 非空且键合法 |
| 方向 | valence 与槽位一致；标 pos 就不能合计为负 |
| 额度 | 影响总额 ≤ budget，单项 ≤ per_attr（`sets` 的成家/生育/丧亲放宽 8 / 2） |
| 自陈 | `requires` 里声明的 married / children_min / child_age_min / parents 必须真的成立 |
| 文本 | 配偶词查 `married`，子女词查 `children`，孙辈词查 `child_age ≥ 22`，父母词查 `parents`（回忆、上坟、遗物例外） |
| 年龄 | 22 岁不退休、40 岁不上小学、13 岁不做工、17 岁不开车 |
| 阶层城乡 | 非贫困家庭不出现挑水/土坯/交公粮；住村庄不出现地铁/写字楼/月供 |
| 年代 | 微信 2011、手机 1996、电视 1978、包产到户 1979、下岗 1994、核酸 2020 |
| 人物 | `id` 必须在册；死人只能作回忆（带 `recall_age` 或写遗物/上坟/梦）；新人物必须有 name/role/mark；一年最多 3 人；文中出现名字就必须登记 |
| 联动 | `recall_age` 和 `links[].age` 必须是真实经历过的年份，且至少隔 2 年；`echo` 必须被接住，或写 `echo_skip` |
| 重复 | 与该人近 24 件事的标题做字符二元组相似度，≥0.5 判重 |
| 旧账 | 到了最后期限的 `open`，必须在 `resolves` 里交代 |

不通过就返回 `{"ok": false, "errors": [...]}`，逐条改完再提交。连改两次还不过，`--fallback` 回落到内置库，不卡住节奏。

## 人怎么进册

```json
"people": [
  {"id": "c1", "act": "把图纸推过来，指了一个位置就没再说话",
   "recall_age": 19},
  {"new": {"name": "孙巧云", "role": "同车间的女工", "rel": "同事",
           "mark": "总把袖口挽到肘上，手上有机油味", "age": 22, "sex": "女"},
   "act": "把饭盒往他那边推了推"}
],
"ties": {"c1": 5, "c3": -3}
```

老人在 `roster` 里，直接用 `id`。新人在 `new` 里报户口，引擎分配 `c{n}` 并永久记住，之后每一年都会被带回 `people.due`。

`act` 是这个人今年做的那一件事，会存成他的 `last_act` 带到明年——所以写具体点，别写「帮了他」。

标了 `dies: true` 的人当场死亡，此后只能在回忆里出现。标了 `owed: "欠着一句没说的话"` 的账，会逐年出现在明年 brief 的 `constraints` 里，直到你用 `paid: true` 划掉它。

**平年也能认识人。** 没有事件槽位的年份，用 `--people` 单独报户口：

```bash
python3 life_engine.py commit --state <S> --people cast.json --status "这一年没什么事"
```

童年蒙太奇就是靠这条命令一次性把家人登记进来的——那 15 年不值得逐年写事件，但那些人值得留在册上。

**年龄要算得过来。** 父母至少比人物大 16 岁，发小、同学要跟人物差 6 岁以内。写错了引擎会算出来，别指望蒙混。

## 旧事怎么接上

```json
"links": [
  {"age": 21, "how": "同一批货，同一种说法，只是这次轮到他开口"}
]
```

`links` 是长期记忆的接口。`then`/`resolves` 只管 1–5 年的短期债务，`links` 能捞回三十年前的事。

两种手段分工：

| 手段 | 时间尺度 | 谁发起 |
|---|---|---|
| `then` → `resolves` | 1–5 年，必须兑现 | 你埋，你收 |
| `echo` → `links` | 5–30 年，可回响 | 引擎挑，你接 |

## 未了结的事（连续性的来源）

事件不是一次性的。写作时用 `then` 埋一件事：

```json
"then": [{"text": "欠了老乡一个人情，早晚要还", "within": 3}]
```

它会带着 pid 进入 `pending`，在期限内的每一年出现在 `open` 里。下一次写事件时，如果这件事该有结果了，就写进 `resolves`：

```json
"resolves": ["p2"]
```

于是下一年的事件自动继承了上一年的因果——不是靠模型记得，而是靠状态存着。

期限到了还没兑现的，会出现在 `slot.must_resolve`，校验会强制要求交代。躲不过去，人生才有负债感。

真没交代呢？引擎不扔，把它转到 `loose_ends`。这本烂账会一直挂着，直到某一年 `echo` 把它翻出来——二十年前欠的那句道歉，四十五岁那年有人上门来要。**人生里最重的债，往往就是这么来的。**

## 事后审计

```bash
python3 life_engine.py audit --state <S>
```

每条历史记录都存了事件发生当时的 `flags` 快照，审计用它回查文本：

- 前后矛盾（未婚写老伴、孩子太小写孙辈、父母已故又出现）
- 五年内同一件事重演
- 父母已故又复活
- 死后还有事件
- 人物已故又在之后的年份以在场身份出场
- 登记在册的人从未被任何事件引用（白建了一个人）

海报之前跑一次，有 issue 就在 beats 里绕开。

## 内置库现在是什么

`references/events.json` 的 195 条**不再是事件池**，它只剩三个用途：

1. `--fallback` 兜底（模型两次写不合规时）
2. `exemplars` 的语感样本
3. 压测与回归测试的固定输入（`tick` 仍走库，用来验证平衡没被改坏）

调平衡时改库仍然有用，但正常游戏里几乎不会读到它。

## 写事件的三条

1. **写事，不写评价**。「他被调到最累的线」是事，「他感到前途渺茫」是评价。
2. **`why` 要落到具体处境**上。同一件事在不同人身上成立的理由不同：失业对 50 岁的人是「厂子搬走了」，对 22 岁的人是「干满三个月就不想干了」。
3. **一年只写一件事**。想塞两件，就把第二件写成 `then`，留给明年。

再加两条：

4. **有人在场，就让他进册**。写名字不登记，这个人下次就接不上了。登记了不写 `mark`，下次认不出他。规则见 `references/people-and-echo.md`。
5. **`echo` 给的事必须接**。接不上就写 `echo_skip`，但一局别超过两次。回响是这套系统的目的，不是装饰。
