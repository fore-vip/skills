# 内容口径与红线

## 一句话

页面是给主题的读者看的，不是给做页面的人看的。任何一句需要知道「这是怎么生成的」才能读懂的话，都该删。

## 叙事顺序

```
首屏价值主张 → 具体项目 / 能力 → 可信证据（案例 / 数字 / 引语） → 行动（预约 / 留资） → 常见疑问
```

`sections` 数组顺序即页面顺序，静态闸门逐项比对：`hero` 在最前，`cta` 存在且不是第一个区块。

不允许：

- 先铺数字，最后一屏才交代「这是什么」
- 先讲怎么用，最后才说「现在到哪一步」
- 正文末尾跳到另一个项目的出品方、作者主页、联系方式

## 文案框架

| 位置 | 要回答的问题 | 写法 |
|---|---|---|
| `hero.h1 + em` | 关我什么事 | 主题专属的一句话，不用通用营销腔 |
| `hero.p` | 凭什么信 | 具体做法与具体边界，不写赋能 / 一站式 / 颠覆 |
| `features` | 到底有什么 | 每项写清对象、时长或条件、价格或代价 |
| `showcase` | 实际怎么发生 | 过程摊开讲，降低第一次来的不确定 |
| `quote` / `stats` | 别人怎么说 | 数字标口径，引语标来源，不编造权威背书 |
| `cta` | 现在做什么 | 留什么信息、会不会有人联系、数据去哪 |
| `faq` | 还担心什么 | 回答最具体的顾虑，不写套话 |

## 主题词审计

每个 spec 必填：

- `meta.requiredTerms`：主题必备词，缺一个即 FAIL。例：美容主题要 `护理 / 皮肤 / 预约 / 美容`
- `meta.forbiddenTerms`：本主题不该出现的词，至少覆盖**其他主题的典型词**、**其他项目品牌**、**旧口径词**

静态闸门另叠加一份通用词表（`生成器 / spec.json / SKILL / 模板生成 / 激活云服务 / publicConfig / applicationId / H5App / KPI / 待办清单 / 现场演示` 等），出现在可见正文即 FAIL。查正文前会剔除 `<head> / <script> / <style>`，技术字符串不算正文；head 内 URL 走单独校验。

## 口径一致性

`meta.disclaimer` 必须原样出现在正文（通常放 `cta.note`），生成器与静态闸门都检查。全文关于「是不是示例 / 有没有上线 / 数据存不存」只允许一种说法：

- 未接后端：明说「没有发送、也不会保存」
- 接了演示表：明说「只写入演示表，不会有人联系你」

不假装成功，不留前后矛盾的两种表述。

## 业务事实必须有来源

页面里凡涉及真实经营的信息——店名、地址、电话、营业时间、项目名、时长、价格、经营承诺、顾客评价——一律不得臆造，逐条登记：

```json
{ "key": "示例价目", "value": "¥198 起", "source": "example" }
```

`source` 取 `user`（用户提供）/ `placeholder`（占位待填）/ `example`（示例）。含 `example` 时 `meta.factReview` 必须为 `true`、口径声明含「示例 / 演示」，交付说明附待补清单；这类页面是演示应用，不得作为真实门店对外发布。

用户没给真实信息时，一次性列出待补清单并停在 INCOMPLETE，不用编造值补齐后当作完成。

## CTA 承诺等于实际能力

- `cloud.needed=true` → 才允许「预约 / 提交 / 立即 / 报名 / 下单」这类强行动词，且表单可提交。
- `cloud.needed=false` → 表单整体禁用，CTA 降级为「看看项目 / 了解流程」，页面写明表单未开放。
- 验收断言只描述应当发生的事，不把「没有发送 / 不会保存 / 未开放」写成 expect 值。
