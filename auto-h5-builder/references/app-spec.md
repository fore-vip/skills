# spec 字段与四页内容

`spec.json` 是唯一内容源。生成器不预设任何业务板块，页面上的每个字都来自这里。

## 一、字段

```jsonc
{
  "store": {
    "name": "暖山美肌",              // 必填，店名
    "slogan": "社区里的面部护理与身体放松", // 必填，首页大标题
    "heroSub": "单次 60 分钟起，提前预约免排队", // 选填，标题下的一句
    "phone": "13800000000",          // 必填，首页可拨、订单联系
    "address": "杭州市西湖区文三路 128 号 2 楼", // 必填
    "hours": "每天 10:00–21:00",     // 必填
    "brand": "#b4735a"               // 选填，主色，默认暖棕
  },
  "services": [                      // 必填，至少 1 项
    { "name": "深层清洁", "price": "¥198", "duration": "60 分钟", "desc": "一句话说明" }
  ],
  "booking": {
    "days": 7,                       // 必填，1–30，可选日期天数
    "slots": ["10:00", "11:00"],     // 必填，时段，24 小时制 HH:MM
    "notice": "到店前 2 小时可改约"   // 选填，预约页底部说明
  },
  "share": {
    "inviteTitle": "邀请好友来做护理",           // 分享页标题
    "inviteReward": "好友首次到店，你得一次头皮舒缓（到店核销）", // 邀请礼，必须能线下兑现
    "posterText": "我在暖山美肌做护理…"          // 可直接复制的推荐话术
  },
  "admin": { "login": "email" },     // email 或 phone，决定管理台的验证码通道
  "cloud": { "bookings": "bookings" } // 固定，与建表脚本保持一致
}
```

## 二、四页各自用什么字段

| 页面 | 取哪些字段 | 不写什么 |
|---|---|---|
| 首页 | `store.*`、`services[]` | 不写经营承诺、疗效、排名 |
| 预约 | `services[].name`、`booking.days/slots/notice` | 不写价格计算、不写在线支付 |
| 分享 | `share.*` | 不写返现、分佣、多级奖励 |
| 店主管理 | `admin.login` | 不写顾客操作说明，页面只服务店主 |

页面不取 spec 的部分：右上菜单四项（预约 / 分享 / 登录 / 退出）是固定文案，`admin.login` 只决定验证码走邮箱还是手机号，不影响菜单。

## 三、文案要求

1. 店名、地址、电话、营业时间、价目、时长必须来自店主。缺哪项就在交付说明里列出来，不编。
2. 服务描述写「做什么」，不写「治什么」。不出现「最」「第一」「根治」「永久」这类词。
3. 邀请礼必须是门店能线下兑现的东西（一次护理、一件小样）。不写现金、不写折扣券码。
4. `posterText` 用第一人称、口语，像顾客自己发朋友圈，不写广告腔。

## 四、改主题不换结构

换一家店只改 spec，四个页面、右上菜单与交互都不变。若某家店确实需要第五个页面（例如商城），单独说明并新建技能，不要往这个范式里塞。

页面之间不共享滚动位置与状态：每页自己的页头、自己的内容区，深链（`#/book`、`#/share`）可单独投放。
