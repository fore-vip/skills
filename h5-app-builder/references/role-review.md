# 六角色验收清单

> 用法：P5 汇报前逐角色回答「必答问题」，命中任一「不合格判据」就回对应阶段修，不许带着它汇报完成。
> 来源：2026-11-12 用户要求「以产品经理、UI 设计师、应用开发、测试、店长、用户的角切入体验产物」后的独立评审复盘。

## 产品经理

| 必答问题 | 不合格判据 |
|---|---|
| 用户要的是应用还是页面草稿？`meta.intent` 与 `meta.deliverable` 一致吗？ | 诉求含「应用 / 上线 / 可发布 / 收预约」，产物只有 `index.html` |
| 核心业务动作有没有闭环？主 CTA 点下去产生什么结果？ | 主按钮只弹「没有发送，也不会保存」；把「业务不可用」写成 PASS 断言 |
| 完成判定锚在哪里？发布或访问地址是什么？ | 用「静态闸门 16/16 + 视口 29/29 + 四张截图」当完成；只有 `127.0.0.1` 预览 |
| 口径是谁定的？有没有单方面把「可交付」降级成「演示页」？ | 用户没说草稿，spec 自己写「示例 / 未开放 / 不接后端」并判完成 |

**历史实证**：专家那次把 `16/16 + 29/29 + 四张截图目视` 写成「最终验证」，而 P5 终点是「本地预览 + 未上线」，全链路没有创建应用环节。

## UI 设计师

| 必答问题 | 不合格判据 |
|---|---|
| 主题一眼可辨吗？版式是路由选的还是套的固定骨架？ | 换个主题读起来照样成立；零命中悄悄用兜底版式 |
| 页内所有可点控件像一家人吗？三档高度、圆角、字号、主色统一吗？ | 8px / 10px / 999px 混用；选中态各写各的 |
| 窄屏导航入口还在吗？焦点态看得见吗？ | `@media(max-width:720px){.hd-nav .nav-link{display:none}}`；`outline:none` 配半透明阴影 |
| 有没有同一句话渲染两遍？截图是否覆盖每个 section？ | `quote` 的 `text` 同时出现在 `.sect-head > p` 与 `<blockquote>`；三张切片漏掉引语区 |

**历史实证**：社区美容页 390px 顶部只剩 logo + 一个按钮，三个导航入口被 CSS 抹掉；引语「下楼就能做，做完也不用被追着问要不要办卡」上下叠了两遍；四张截图没有一张覆盖 quote。

## 应用开发

| 必答问题 | 不合格判据 |
|---|---|
| 站点地址真实吗？canonical / og:url / ld+json.url 三处一致吗？ | 三处都是 `https://example.com/index.html`；草稿态还写自引用 URL |
| 表单有落点吗？没接后端时控件是否整体禁用？ | `<form>` 无 action/method，按钮可点，`preventDefault` 后只弹提示 |
| JS 关闭 / 键盘操作会怎样？ | 无 `<noscript>`、无 `<label>`、状态条无 `role/aria-live`、装饰 svg 无 `aria-hidden` |
| head 元数据自洽吗？ | 声明 `twitter:card=summary_large_image` 却没有 `og:image`；没有 favicon |
| 技术词有没有漏进正文或脚本注释？ | `publicConfig` / `H5App` / `spec.json` 出现在页面全文 |

**历史实证**：生成器 `--base-url` 默认值就是 `example.com`；`verify_static.py` 整段删掉 `<head>` 再查词，head 内 URL 从设计上就看不见。

## 测试

| 必答问题 | 不合格判据 |
|---|---|
| 五道闸门逐道结果是什么？ | 只跑静态与视口；没跑 `verify_delivery.py` |
| 双视口都跑了吗？桌面导航与溢出验证了吗？ | 只跑 390×844；`@media(max-width:720px)` 与 1080 容器是未回归代码 |
| 截图是否逐 section 输出、数量是否够？ | 手工补一张 cta 图，声称「四张目视通过」却无法复现 |
| 断言模板有没有盲区？失败路径测了吗？ | 断言只查含词与样式，不查域名、去重、导航可见、a11y、JS 关闭；CDN 不通时无可见提示 |
| 有没有把「不可用」写成验收项？ | `expect: "没有发送"` / `expect: "不会保存"` 被判 PASS |

**历史实证**：同页存在假域名、引语重复、有表单无后端、CTA 能力冲突，`verify_static.py` 仍输出 `RESULT ALL PASS (16)` —— 全绿是假阳性。

## 店长（真实业务方）

| 必答问题 | 不合格判据 |
|---|---|
| 店名、地址、电话、营业时间、项目、时长、价格是用户提供的吗？ | 由 AI 编造「巷里养肤」「¥198 / ¥168 / ¥268」「60 / 45 / 75 分钟」 |
| 经营承诺是店长定的吗？ | 页面替店长写「不办卡 / 不加项 / 改约不收手续费 / 同一时段只安排一位」 |
| 顾客评价真实吗？ | 编造邻里口碑并用于获客，即使标「示例反馈」也有虚假宣传风险 |
| 留下来的线索去哪了？ | 页面收手机号却不发送不保存，店长一条线索都拿不到 |
| 页面能不能对外发布？ | 含 `example` 来源的事实却没标「演示应用，禁止对外发布」 |

**规则**：所有业务事实登记在 `meta.facts`，`source` 只能是 `user / placeholder / example`；含 `example` 必须 `factReview: true` 且口径声明含「示例 / 演示」，交付说明附「待补事实清单」。

## 终端用户

| 必答问题 | 不合格判据 |
|---|---|
| 点主按钮后得到什么？ | 填完称呼和手机号，提交后被告知「白填」，且没有电话 / 地址 / 到店等替代动作 |
| 能不能判断这店是真的、能不能约？ | 导航写「预约护理」、Hero 写「约一次到店护理」，按钮却写「（示例）」、页脚写「未开放真实预约」 |
| 决定「值不值得来」的信息齐全吗？ | 强调「下楼就能做」却无地址、营业时间、真实价目；价格全是示例价 |
| 移动端能不能直达想看的区块？ | 导航被隐藏，只能盲滚；表单不可用时没有任何说明 |

**规则**：没有后端就把表单整体禁用并明确标注，不给「看起来能点」的按钮；CTA 文案不得含「预约 / 提交 / 立即」这类强行动词，除非 `cloud.needed=true`。

## 本次修复台账（问题 → 落点）

| 问题 | 修复 | 由哪道闸门守住 |
|---|---|---|
| 没有应用创建环节，完成判定锚在页面 | 新增交付形态契约 + P3.5 + 三态判定 | `verify_delivery.py`、SKILL 第 0 节 |
| 假域名 `example.com` | `--base-url` 取消默认值；草稿态不写 head URL；三处 URL 强一致 | 生成器自检、`verify_static.py` |
| 引语重复渲染 | renderer 用 `owns` 声明字段所有权，不再按类型打补丁 | 生成器自检、`verify_static.py` 去重断言 |
| 窄屏导航被抹掉 | 改为第二行横向滚动；焦点态改实线描边 | `verify_static.py` CSS 断言、双视口导航可见断言 |
| 表单假提交、白填手机号 | 无后端时 input/button 全禁用 + `<noscript>` + 强行动词拦截 | 生成器自检、`verify_static.py` |
| 臆造业务事实 | `meta.facts` 来源清单 + 待补清单 + 演示应用警告 | `verify_static.py`、`verify_delivery.py` |
| 只跑 390 单视口、截图漏段 | 默认 390 + 1280，逐 section 截图落交付目录 | `verify_viewport.mjs`、`verify_delivery.py` 覆盖度 |
| 把「不会保存」写成 PASS 断言 | 静态闸门与该断言模式直接判 FAIL | `verify_static.py` |
| 技术词只在可见正文查 | 全文扫描（含脚本注释与变量名） | `verify_static.py` |
