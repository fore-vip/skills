# 验证闸门与已知坑

## 一、四道闸门（交付前逐道留证据）

| # | 闸门 | 通过标准 |
|---|---|---|
| 1 | 生成器自检 | 占位符清零、标签平衡、零外链、口径齐备、JS 语法；非零退出即阻断，不产出半截文件 |
| 2 | 静态引用 | 页面内所有本地引用可访问，零 404 |
| 3 | 真实视口交互断言 | 全部 PASS，含 `innerWidth` 回读与 `scrollWidth <= 视口宽` |
| 4 | 截图目视 | 首屏 / 演示区 / 第二 TAB 各一张，人工看无截断、无重叠、无错位 |

断言要覆盖「改维度联动 / 改状态回写 / 深链 TAB / 无横向溢出」，只截一张图不算验证。

## 二、真实视口坑（最容易误判）

无头浏览器 `--window-size=390,844` 常被夹到**最小 500 逻辑宽度**，截图看起来像右侧内容被裁，其实是视口设错了、页面没问题。

正确做法：起带 `--remote-debugging-port` 的无头浏览器，用 CDP `Emulation.setDeviceMetricsOverride` 强制 390×844，再回读 `innerWidth` 确认。`scripts/verify_viewport.mjs` 已封装，断言从 spec 读。别用裸 `--window-size` 下结论。

## 三、生成器自检的两个误报

- 大小写不敏感地搜 `TODO` 会把 CSS/HTML 类名 `.d-todo` 命中（"d-todo" 含连续 "todo"）。只认**大写独立词** `\bTODO\b|\bFIXME\b|\bXXX\b`。
- 标签平衡检查要覆盖 `table/tr/th/td` 等表格标签；只查 `div/section` 会漏掉表格错位。

## 四、口径红线

- 页面出现示例数据时，首屏、演示区、说明区三处都要写明「示例数据 / 刷新复位 / 未开放安装（若确实未开放）」。
- 不做看起来能点、实际没有的安装/提交/付费按钮。没开放的能力就如实写没开放。
- 技术名词不出现在面向用户的正文里（站名、接口、部署、服务器、SDK 等），容易被当成已上线能力。
- 「代码已提交」≠「已上线」，本地预览 ≠ 线上发布。上线是对外动作，必须有明确指令。

## 五、可选适配层（既有站点才做）

目标是已有站点时要勾：入口卡 / 分享卡与 meta / sitemap 或路由 / 结构一致性清单 / 兄弟页互链 / 发布闸门预演。

> **AUTO 站点的一个已验证参考实现**：`templates/scene.html` 派生、`verify_oss_landing.py --strict`、`check_scene_parity.py`、`check_assets.py --quiet`、`gen_og.py`、`sync_sitemap.py`、`deploy.sh -n`。它们是**参考**，不是本技能的依赖：生成 OG 图需要带图像库的解释器；重跑生成器会刷新既有分享卡时间戳导致无谓重传（字节可能完全没变）；`deploy.sh` 自带 sitemap 一致性闸门，未同步会直接中止发布。换站点请换成该站点自己的对应物，别硬套路径。

## 六、本机工具链已知坑（跨项目通用）

- 同一文件多个编辑操作必须串行；报错不代表没改，改完一律重读复核。
- 编辑会把 CRLF 文件整篇转 LF，造成几百行假 diff；改完用 `git diff --numstat` 核对数量级。
- BSD `grep` 不支持 `\|` 交替，用 `grep -E 'A|B'` 或 ripgrep；BSD `sed -i ''` 易失败，改用 `perl -ni -e`。
- 静态预览服务必须常驻后台，临时 `&` 起的会被回收，表现为页面打不开。
- 浏览器自动化守护进程不会自动退出，任务结束（无论成败）都要关闭并复查进程为空。
- 含脚本的页面在某些浏览器工具里只能得到安全占位页；无脚本的本地静态页可正常截图。
- 一次性输出上千字连贯中文时，可能随机插入无意义外文词。长稿落盘后做两道机器预检：禁用词/噪声词正则 + 全文英文词集与白名单求差集人工过。
- 工作树里有别人的活时，只暂存自己新增的路径，不要整目录 `git add` 把半成品裹进来。

## 七、云模式新增的四道附加检查

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 生成自检（云模式） | 唯一 SDK 白名单脚本存在；`createWorkBuddyCloud` 存在；初始化从 `publicConfig` 取 `endpoint`；无内部字段泄漏 |
| 2 | 管理侧写入读回 | `INSERT` → `SELECT` → 冲突更新 → 再 `SELECT`，值与预期一致 |
| 3 | 前端端到端 | 点击后数据库真的变了；重新加载页面后状态还在；失败时页面有可见提示而不是静默 |
| 4 | 失败路径 | 屏蔽 SDK / 网络失败 / 权限拦下 / 空结果，各有清晰提示；本地交互不被云故障拖垮 |

补充坑：

- 云页面要留足 SDK 加载时间，`verify_viewport.mjs` 用 `--wait 6000`；用默认 1500 毫秒会把「还没连上」误判成功能坏了。
- 静态引用检查要区分「运行依赖」与「导航 / 元信息外链」；`canonical`、作者主页不是运行依赖。
- 结构化工具的 `RLSOn` / 注释字段可能滞后，关键状态用只读 SQL 复核。
- 跑断言前把云表复位，否则「剩余件数」类断言会被上次运行留下的状态带偏。
- CDN 时通时不通时，一次 PASS 不能当稳定结论，要同时给出连通与失败两条证据。
