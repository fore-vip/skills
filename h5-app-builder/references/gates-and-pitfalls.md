# 四道闸门与本机坑

## 闸门（按顺序，缺一不可）

| # | 命令 | 挡住什么 |
|---|---|---|
| ① | `build_page.py` 内建自检 | 占位符残留、标签不平衡、外部依赖、口径声明缺失、JS 语法错误；**不过就不写盘** |
| ② | `verify_static.py --spec x.json --page index.html [--cloud]` | 主题词缺失 / 串台、制作过程词入正文、叙事顺序错、旧控件类、内联样式、`.ctl` 硬编码尺寸色值、云接线白名单 |
| ③ | `verify_viewport.mjs --spec ... --url ... --shots ...` | 视口不真、页内圆角 / 高度 / 字号 / 主色不一致、输入框与控件不同形、内联样式、spec 业务交互断言 |
| ④ | 目视 hero / mid / bottom 三张截图 | 自动断言管不到的观感：主题是否一眼可辨、品牌是否统一、有无截断 / 溢出 / 错位 |

云模式的 ② 要加 `--cloud`。两道脚本都返回非零退出码表示失败，不要只看最后一行输出就宣布通过。

## 视觉一致性最容易漏的地方

- 自动断言只比对 `.ctl`；新增自定义可点元素时，必须挂 `.ctl` 基类，否则不会被检查到
- CSS 里新增 `8px` 之类的字面量会立刻被 ② 拦下 —— 抽成 `:root` 变量
- 静态标签用 `.tag`，不要让它长得像按钮（无 hover / 无 pointer），否则读者分不清哪些能点
- 输入框 `.field` 的高度与圆角必须和同排控件一致，③ 会逐项比对
- 「页内统一、跨主题不同」是判定原则，别把跨页差异当 bug 修掉

## 本机环境坑

- 无头 Chrome 的 `--window-size=390,844` 会被夹到最小逻辑宽度 500，截图会变成裁剪图。必须走 CDP `Emulation.setDeviceMetricsOverride`，并在断言里回读 `innerWidth`
- 云 SDK 的 CDN 在本机时通时不通（`curl` 返回 000）；慢速单发重试、结果做合理性断言，别把一次失败当结论
- `python3 -m http.server` 必须用后台任务常驻；用 `&` 起的会被回收，表现为页面打不开
- 工作树里有别人的活时只暂存自己新增的路径，别整目录 `git add` 把半成品裹进来
- 同一文件多个 Edit 必须串行；关键大段改动优先整体重写，写完复读核对
- 长稿写完做两道机器预检：广告法禁用词 / 噪声词正则，再抽 `[A-Za-z]{4,}` 词集与白名单求差集人工过一遍

## 交付边界

- 页面生成、验证通过 ≠ 已上线。本地预览、应用卡片、git 提交、SkillHub 发布是四件事，逐件如实标注
- 发布预演用 `--dry-run` 之类只读方式，正式发布与上线都要用户明确指令
- 云服务确认框被取消就记「未接入」，不重试不绕路
- 表单没接后端就明说没接，别做看起来能点、实际什么都没发生的假提交
- 每次跑出新的主题或新的坑，回写 `examples/` 与 `references/`，别让下一次重新踩
