# 报告模板

出报告前读。照此结构输出，**不要自由发挥成散文**。

## 结构约定

| 顺序 | 板块 | 硬要求 |
|------|------|--------|
| 1 | 需求复述 | 一行，确认没跑偏 |
| 2 | 五家候选一览 | 表格，标明品牌/创新企业属性与数据完整度 |
| 3 | 评分表 | 8 子项 + 三小计 + 总分 + 等级，一家一行 |
| 4 | 排名与推荐结论 | 前 3 名，各写「凭什么赢」+「已知短板」 |
| 5 | 前 3 名官方旗舰店 | 平台 + 店铺全名 + 检索路径 |
| 6 | 信源清单与免责 | 逐条列来源与日期 + 免责声明 |

**措辞纪律**：禁用「最 / 第一 / 唯一 / 保证 / 100%」等绝对化用语；
结论限于「本次 5 家候选中」的横向比较，不写成行业排名。

## 二、数据完整度不足时的改写

当某企业数据完整度 < 50% 时，**不列入确定排名**，改用下表放在评分表之后：

```markdown
## 无法可靠评估的企业

| 企业 | 数据完整度 | 缺什么 | 建议 |
|------|-----------|--------|------|
| {企业名} | {n}/8 | P1 用工类证据缺失，公开渠道无员工口碑 | 建议直接咨询在职员工或查看脉脉最新评价后再判断 |
```

并在「推荐结论」开头加一句：

> 注：{企业名} 因公开证据不足，本次不作排名，避免给出不可靠的确定结论。

## 三、HTML 评分卡（`--html` 输出）

`scripts/score.py --html` 会生成一份自包含的可视化报告，结构如下，样式由脚本内置：

| 区块 | 内容 |
|------|------|
| 头部 | 品类标题 + 权重说明 + 生成日期 |
| 排名卡列表 | 每家一张卡：排名徽章、企业名、等级色块、百分制总分、三维度进度条 |
| 评分明细表 | 8 子项得分的全表对比 |
| 旗舰店表 | 前 3 名官方渠道 |
| 页脚 | 免责声明 |

**设计约束**：浅色底 + 深色文字（无深色主题时以浅色为默认）；
等级配色 S 绿 `#16a34a` / A 黄绿 `#84cc16` / B 黄 `#eab308` / C 橙 `#f97316` / D 红 `#dc2626`；
不引外部资源（无 CDN、无外链字体），保证离线可开。

## 四、措辞对照表（自查用）

| 不要写成 | 改写成 |
|----------|--------|
| 该企业违法用工 | 公开信息显示存在劳动争议（附文书） |
| 这家公司就是 996 | 社区中有多条关于加班的描述，未获企业确认 |
| 质量最差 | 在本次候选中质量风评相对靠后 |
| 保证双休 | 招聘信息与员工反馈均显示为双休制度 |
| 没有劳动纠纷 | 本次检索未发现公开的劳动纠纷记录 |
| 第一 | 本次候选中排名第一 |

**最后一条尤其重要**：「未发现」和「没有」是两回事，报告里永远写前者。
