# 双休了么 · 用消费投票的购物决策助手

用户说「我想买 XX」，本技能不只回答**买哪个产品**，而是回答**买哪个企业的产品**——
把「双休 / 标准工时 / 不欠薪 / 没有劳动纠纷」变成选购的可量化维度，
让用户的每一笔钱都落在善待员工的企业上。

一句话流程：**问需求 → 组 5 家（3:2）→ 四路取证 → 三维评分 → 排名 + 前 3 家旗舰店**。

## 适用与边界

| | 内容 |
|---|---|
| **本技能做** | 按企业用工口碑筛选购物选项；五家候选的横向评分排名；前 3 名官方旗舰店地址 |
| **本技能不做** | 产品参数评测、性能对比、值不值得的性价比判断 |
| **本技能不做** | 全网比价、优惠券、券后价排序 |
| **本技能不做** | 劳动维权方案、法律定性、代写举报材料 |
| **本技能不做** | 求职推荐、简历与面试辅导 |

> **与既有技能的分工**（不要越界抢活）：
> - `fore-vip-shopping-saver` 管**价格**（哪里最便宜、券在哪）→ 本技能管**企业**（谁对员工好）。
> - `fore-vip-product-recommend` 管**产品本身**（参数、选型）→ 本技能管**生产者**。
> - `fore-vip-workplace-survival` 管**在职维权**→ 本技能只用公开信息做消费侧的横向对比，不给法律结论。
>
> 两者可串联：本技能定「买哪家」，再交给比价技能定「在哪买最省」。

## 触发规则

| 用户意图 | 处理 |
|---|---|
| 「双休了么：想买个 XX」 | 进入五步流程 |
| 「哪个牌子的 XX 是双休的公司做的」 | 进入五步流程 |
| 只说了品类，没说具体商品（「想换个吹风机」） | 先问清需求，再进入流程 |
| 指定了品牌（「XX 和 YY 哪个好，从员工角度」） | 保留用户指定品牌，补足至 5 家后再评分 |
| 只问本技能能干嘛 | 仅介绍，不展开 |

## 四条底线（先于一切，不可为）

1. **信息必须可溯源**。每条评分依据都要带**信源 + 时间**。查不到就写查不到，
   绝不填充、推测、编造企业用工情况。宁可标「信息不足」也不给结论。
2. **不作法律定性**。劳动纠纷、欠薪、违法用工等，只说「公开报道/裁判文书显示存在争议」，
   不替法院或人社部门认定某企业违法。判定归属一律以官方文书为准。
3. **不传播未证实的负面指控**。单方爆料、匿名帖、传闻必须标注「未证实（单方主张）」，
   与已生效法律文书的信息分级呈现，不混为一谈、不做定论式表述。
4. **不违反广告法**。禁用「最 / 第一 / 唯一 / 保证 / 100%」等绝对化用语；
   评分只在本次候选范围内横向比较，明确不等于官方评级。

## 五步流程

### 第 1 步 · 问清买什么（不要直接开搜）

用 AskUserQuestion 一次问清最多 4 项：

| 必问 | 为什么 |
|------|--------|
| 买什么品类 / 具体商品 | 决定候选池与检索关键词 |
| 用途与关键指标 | 决定「产品风评」维度看什么 |
| 预算区间 | 决定候选品牌档次，避免推荐买不起的 |
| 已有偏好或必须避开的企业 | 用户可能有既定立场，先问再补位 |

缺项按最保守假设推进并标注「此处按假设处理」。**绝不在没问清品类时直接给排名。**

### 第 2 步 · 组 5 家候选（3:2 结构）

按 **3 : 2** 组池——这是本技能的方法学关键：

| 类别 | 数量 | 选取口径 |
|------|------|----------|
| 成熟品牌 | **3 家** | 该品类的市场主流/头部，用户大概率已经知道的那几个 |
| 创新企业 | **2 家** | 新锐品牌、设计驱动型、DTC 品牌、跨界入场者 |

> **为什么是 3:2**：成熟品牌规模大、流程重、加班文化固化（也更容易被公开记录），
> 创新企业机制灵活、更可能真双休（但公开信息少、抗风险能力弱）。
> 两类混编才能看出「用工友好」是不是规模带来的奢侈品。
> 用户明确指定候选时保留其指定，剩余名额按此结构补齐；总数仍为 5 家。

### 第 3 步 · 四路取证

对 5 家企业逐一路过以下四类信源，**每类至少取一条证据**：

| 信源 | 取什么 | 典型渠道 |
|------|--------|----------|
| **模型基础档案** | 企业规模、性质、成立时间、主营、上市状态、供应链模式 | 模型已有知识 + 官网/年报 |
| **社区** | 员工真实口碑（工时、加班、双休、社保、裁员方式） | 脉脉、知乎、小红书、豆瓣、贴吧 |
| **搜索引擎** | 补充检索，覆盖社区未提的侧面 | 通用检索，按「企业名 + 关键词」组合 |
| **资讯站** | 劳动纠纷、仲裁判决、行政处罚、欠薪报道、ESG/社会责任报告 | 裁判文书网、信用中国、劳动仲裁公告、财经媒体、黑猫投诉 |

具体渠道清单、检索式模板与信源可信度分级见 `references/sources.md`。
正负信号词库（用来快速判定命中）见 `references/flags.md`。

### 第 4 步 · 三维度评分排序

每个子项按 0–5 分打分，乘以权重加总为百分制总分：

| 维度 | 权重 | 子项 |
|------|------|------|
| **P1 用工友好与工时** | 45 | P1.1 双休制落实(18) · P1.2 实际加班强度(15) · P1.3 加班补偿落实(12) |
| **P2 劳动合规与雇主口碑** | 30 | P2.1 劳动纠纷/仲裁记录(12) · P2.2 社保与用工合规(8) · P2.3 员工社区口碑(10) |
| **P3 产品质量与供应链** | 25 | P3.1 产品质量风评(15) · P3.2 供应链用工与稳定性(10) |

总分 = Σ(子项得分 ÷ 5 × 子项权重)，映射等级：

| 等级 | 分数 | 含义 |
|------|------|------|
| S | ≥ 85 | 良心雇主，可放心支持 |
| A | 70–85 | 值得买，用工记录良好 |
| B | 55–70 | 谨慎考虑，存在明确短板 |
| C | 40–55 | 有争议，建议对比后再定 |
| D | < 40 | 建议避雷，用工问题突出 |

评分锚点（每个分值对应什么证据）、证据类型与判定规则详见 `references/dimensions.md`。

**信息不足的处理（强制）**：
- 某子项查不到证据 → 记为 `null`，按行业中位 3 分代入，并在报告中标注「信息不足·按中位代入」。
- 同时输出**数据完整度**（有实证的子项占比）。完整度 < 50% 的企业，
  结论必须加「证据不足，评分仅供参考」的显式提示，不得排出确定名次。
- 不许用模型印象分冒充检索所得，两者要分开标注。

用脚本算分与排名（避免手算漂移）：

```bash
python3 scripts/score.py -i scores.json -o report.md              # Markdown 报告
python3 scripts/score.py -i scores.json -o report.md --html r.html  # 附 HTML 评分卡
python3 scripts/score.py --template-demo                          # 打印输入 JSON 样例
```

### 第 5 步 · 输出报告与前 3 家旗舰店

报告固定包含六块：

1. **需求复述** —— 买什么、用途、预算、偏好（确认没跑偏）
2. **五家候选一览** —— 企业名、成熟品牌/创新企业、一句话定位、数据完整度
3. **评分表** —— 8 个子项得分 + 三维小计 + 百分制总分 + 等级
4. **排名与推荐结论** —— 前 3 名，各写「凭什么赢」与「已知短板」
5. **前 3 名官方旗舰店地址** —— 见下方规则
6. **信源清单与免责** —— 每条证据的来源与日期，附本技能的不确定性声明

**旗舰店地址规则（重要）**：

- 优先给**官方渠道**：品牌官网商城、天猫官方旗舰店、京东自营/官方旗舰店、抖音官方旗舰店。
- 给「**平台 + 店铺全名 + 检索路径**」，不要凭记忆拼 URL。
  确有把握且可核实的官方域名才写链接；不确定就给检索方式让用户自己点。
- 必须提示：**认准平台官方认证标识**（天猫品牌旗舰店、京东自营/官方旗舰店、抖音蓝V官方店），
  避免买到「XX 专卖店 / XX 海外专营店」这类易混淆店铺。
- 平台与店铺状态会变，见 `references/report-template.md` 的写法约定。

## 输出风格

- 结论先行：先说前 3 是谁，再展开证据。
- 表格化：评分必须成表，不做大段散文描述。
- 去 AI 味：不用 emoji 分块，句式长短交替，不堆营销词。
- 不确定就说不确定：信源薄的地方明确写薄，不硬凑。
