## 2. 站点认证（所有提交的前提）

**未完成站点验证，平台里大部分操作无效，配额也拿不到。**

三种方式，任选其一：

| 方式 | 操作 | 优点 | 缺点 |
|------|------|------|------|
| **HTML 文件验证** | 下载平台给的验证文件，放到网站根目录 | **最快、最推荐**，不依赖解析生效 | 需确保文件不被误删、不被 robots 屏蔽 |
| **HTML 标签验证** | 在首页 `<head>` 插入一段 `<meta>` | 一次改模板全站生效 | 只对首页生效，改模板要记得保留 |
| **DNS 验证** | 解析里加一条 TXT（或 CNAME）记录 | 不受站点内容变更影响 | DNS 生效有延迟，各平台记录名不同 |

**关键细节**

1. 验证文件/标签放好后，**先 `curl` 确认公网可访问**（`200`，不是 `403`/`404`），再去平台点「验证」。
2. **`http` / `https`、`www` / 裸域 可能需分别验证**。选一个为规范域，其余做 301 跳到规范域。
3. **提交时地址要和验证的域一致** —— 别用 `www` 验证的 token 去推裸域链接。
4. 认证文件与 `robots.txt` 里的 `Disallow` **不要互相冲突**（把验证文件路径加白名单）。
5. OSS 场景注意对象权限：验证文件必须**公共读**，否则平台取到 `403`。

## 3. 提交方式与优先级

以百度为例（其它平台逻辑类似，界面文案不同）：

| 方式 | 时延 | 配额 | 适用 |
|------|------|------|------|
| **API 主动推送** | 最快（数小时级） | 高于手动，按站点质量评估 | 更新频繁的站，接进发布流程 |
| **sitemap 提交** | 1–3 天 | 天级配额 + 存量文件配额 | **必做**，覆盖全站、长期有效 |
| **手动提交 URL** | 3–7 天 | 每日有配额 | 新站初期推核心页，每天少量 |
| 快速收录（需申请权益） | 48 小时内 | 需满足质量门槛 | 高时效内容；**仅限移动端页或自适应页** |

百度配额机制（官方口径）：平台基于**站点资源质量与搜索用户偏好**综合评估计算提交配额，站点不同配额不同；提交大量重复、违规、低质资源会被**降低配额**。可在「资源提交 → 普通收录」界面查看天级提交配额与存量文件配额。

> 索引型 sitemap 文件不予处理；若存在需先删除再提交。

## 4. 分平台要点

### 百度搜索资源平台

- 验证 → 提交 sitemap → 用「URL 提交」推 1–2 条最新 URL 触发即时抓取。
- 跳转链接（短链、301）**直接提交跳转后的最终目标链接**。
- 换域名后要**及时提交新域名资源**，并在平台做站点改版/域名变更申报。
- 死链提交：**仅识别 404**，格式仅 `txt` / `xml`，单文件 ≤ 5 万网址且 ≤ 10 MB；误提交非死链内容不生效；处理后抓取生效约 1 周。
- 有单独移动站点时提交移动 Sitemap 协议；自适应/响应式站不需要。
- `robots.txt` 里声明 sitemap，同时在平台后台提交，双保险。

### 必应 Webmaster Tools

- 支持**从 Google Search Console 一键导入**已验证站点与数据，省掉重复认证。
- 提交 sitemap 后 2–3 分钟刷新页面确认状态为「成功」。

### Google Search Console

- 两种资源类型：**「网址前缀」**（单协议 + 单主机，验证简单）与**「网域」**（覆盖所有子域与协议，需 DNS TXT）。有多个子域选「网域」。
- `Sitemaps` 栏输入 `sitemap.xml` 提交；未立即生效属正常。
- 用「网址检查」对首页做一次实时抓取，确认 Googlebot 能正常渲染。

### 360 / 神马 / 搜狗 / 头条

- 认证与提交逻辑同百度（验证文件 / meta / DNS + sitemap URL）。
- 入口界面与配额规则变动频繁，**以打开后的实际界面为准**；若某平台已停止服务或不再支持新站提交，如实说明并跳过，不要硬填。

## 5. 注意事项与常见驳回

**站点侧前提（缺一项都会被拖慢或拒收）**

1. 域名已备案、服务器在国内、可稳定访问 —— 境外与未备案站收录慢。
2. **全站 HTTPS**（百度优先抓取）。
3. 页面加载 ≤ 3 秒；移动端适配良好（响应式 ≤ 3 档断点）。
4. `robots.txt` **不屏蔽**重要页面；不要用 `robots.txt` 做「禁止索引」（那是禁止抓取）。
5. 每页唯一 TDK（title / description / keywords），不重复、不堆砌。
6. 文本可抓取 —— 避免纯图片站、全 JS 渲染且无兜底内容。
7. 首页在 3 次点击内可达所有重要页面，有清晰文字导航与内链。

**平台侧高频问题**

| 现象 | 原因 | 处置 |
|------|------|------|
| 验证失败 | 文件不可公网访问 / 标签不在首页 / DNS 未生效 | 先 `curl` 自查，再等 TTL，不要反复删了重加 |
| sitemap 长期「待处理」 | 配额耗尽 / 含低质或重复 URL | 精简到真实有效页面，剔除参数页与重复页 |
| 提交后索引量不涨 | 内容质量或重复度高 / 被判定低质 | 提升原创与信息增量，稳定更新频率 |
| 平台提示「站点改版」 | 结构或域名变更未申报 | 在平台做改版规则申报 |
| www 与裸域各收录一半 | 未指定规范域 | 选一个为规范，另一个 301 + `canonical` 指规范域 |

## 6. 执行顺序清单

```
① 站点上线并验证可访问（见 hosting.md §7）
② 生成并发布 robots.txt + sitemap.xml（seo_audit.py 闸门通过）
③ 选一个规范域，另一个 301 跳转，canonical 全站指向规范域
④ 百度搜索资源平台：认证 → 提交 sitemap → URL 提交推最新页
⑤ 必应 Webmaster：GSC 导入或直接认证 → 提交 sitemap
⑥ Google Search Console：认证 → 提交 sitemap → 首页实时抓取检查
⑦ 按访客分布补 360 / 神马 / 搜狗 / 头条
⑧ 记录每平台的认证文件位置，纳入「不可删除清单」
⑨ 上线后第 3 天 / 第 7 天回后台看抓取状态与索引覆盖率
```
