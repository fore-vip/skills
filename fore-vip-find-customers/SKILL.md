# 找客户 · B2B 客户挖掘与获客助手

把模糊的「帮我找客户」转化为**有来源、可联系、可执行**的客户线索清单；线索稀有时反向补偿——告诉用户去哪发布供给信息、怎么发合规、配什么图。

**适用**：B2B 找下游买家、拓销售渠道、挖掘潜在客户、行业客户画像分析。
**不适用**：C 端流量投放、CPS 转链选品、代发广告（见末尾关联技能与边界）。

## 触发规则

| 用户意图 | 处理 |
|----------|------|
| 找客户 / 帮我找客户 / 客户挖掘 / 获客 / 潜在客户 / 下游客户 / 销售线索 | 进入找客户流程 |
| 我的货 / 服务卖给谁 | 进入找客户流程（从下游分析切入） |
| 只问本技能能干嘛 | 仅介绍，不展开 |

## 核心准则（来自 fore.vip 身份）

- **先结论后依据**：开头一句话给「下游是谁 + 最优先客户群」，再列清单。
- **事实 / 分析 / 建议 三级分离**：采集到的信息（事实）、匹配判断（分析）、行动建议（建议）不混淆。
- **数据可溯源**：每条客户线索标注 `来源·时间·适用范围`，查不到就标「待验证」。
- **合规红线**：只用公开渠道信息；不采集身份证号、私密联系方式等隐私数据；发布内容不做硬广、不虚假承诺，符合广告法与平台条款。

## 找客户流程

### 1. 需求采集（锁画像）

开始前必须明确，缺失则用**至多 1 轮追问**补齐（合并提问，不逐个轰炸）：

- **行业**：用户处于什么行业、卖什么产品 / 服务？
- **产品定位**：核心卖点、价格带、起订量 / 服务方式？
- **目标区域**：本地 / 全国 / 跨境？有无既有客户样本？
- **期望客户画像**：想找哪类买家（规模、渠道角色、决策人）？

### 2. 下游分析（定方向）

基于产业链推导「谁会买」，输出一张下游地图：

| 下游行业 | 概要 | 对用户产品的需求点 | 优先级 |
|---|---|---|---|
| [行业 A] | 规模/格局/区域分布一句话 | 为什么需要、怎么用 | 高/中/低 |

- 优先级按「需求强度 × 可触达性 × 决策周期」综合判断。
- 区分事实（行业数据）与分析（推断的匹配逻辑），数据标 `来源·时间`。

### 3. 多源客户采集（找线索）

按优先级对下游行业逐个采集，来源分层汇聚：

| 来源层 | 说明 | 标注要求 |
|---|---|---|
| 行业门户 / 协会网站 | 下游行业的 B2B 平台、展会名录、协会会员名单 | 站点名·时间 |
| 搜索引擎 / 官网 | 公司官网「关于我们 / 联系我们 / 采购信息」 | URL·时间 |
| 社区 / 垂直频道 | 行业社群、贴吧、知乎、小红书、1688 等平台的公开企业信息 | 平台·时间 |
| 大模型知识兜底 | 既有行业知识中的典型企业，**必须标「模型知识·待验证」** | 待验证 |

- 每个下游行业先给「该行业信息最好的 N 个入口（门户/名录/频道）」，再列客户。
- 联系方式只取**官网或公开平台主动公示**的（公司电话、公开邮箱、工商信息）；责任人姓名查不到就写「待查」，不推测编造。

### 4. 客户清单输出（给结论）

先一句话结论，再给清单：

```
## 结论
[一句话：下游主攻 X 行业，最优先客户群是 Y，已汇聚 N 条线索]

## 下游地图
[第 2 步的表格]

## 客户清单
| 公司 | 下游行业 | 责任人 | 联系方式 | 官网 | 匹配度 | 来源·时间 |
|---|---|---|---|---|---|---|

- 匹配度分高/中/低，一句话理由放表注。
- 联系方式缺失的标「待查（建议渠道：官网表单/公众号/电话）」。

## 所以呢（行动建议）
- [按匹配度排序的触达动作，如：先联系 A 公司采购部，入口是其官网表单]
```

### 5. 邮件直推（客户有公开邮箱即推）

对第 4 步清单中**带公开邮箱**的客户，走一对一触达（不限于稀缺场景）：

- **图内嵌联系方式**：与公开发布不同，直推图允许把用户的联系方式（微信 / 电话 / 邮箱）合成到图片角落水印位——一对一触达非公开平台，无平台限流与敏感词风险。
- **配图输入**：图仍由用户提供参考图 / 提示词生成（见 Step 6 第 3 步输入规则），仅在最终图上叠加联系方式水印，不脱离用户提供的素材与卖点。
- **经 Agent Mail 推送**：按文末「Agent Mail 配置」声明调用（agent-mail MCP 的发送与附件接口），主题与正文走合规话术，附件附上合成图。
- **合规**：邮件正文不夸大、不承诺保量，符合《广告法》；收件邮箱须来自公开渠道，不发送未授权批量邮件（避免被标记垃圾邮件）。

### 6. 稀缺补偿 · 发布获客（反向找）

当客户线索相对稀有（可联系客户 < 5 条或行业信息分散）时，主动切换为「让客户找上门」模式：

1. **给渠道清单**：按用户产品匹配发布渠道（B2B 平台、行业社群、朋友圈/公众号、本地生活平台等），渠道库与适用判断见 `references/channels.md`。
2. **给发布范式**：按所选渠道给可直接套用的发布文案模板，必须符合对应平台 / 社区合规条款（见 `references/channels.md` 各渠道范式）。
3. **生成图文（须用户给定输入）**：生成配图前必须先取得用户提供的**参考图 或 提示词**，二者皆缺则向用户索取其一（给示例：参考图＝产品实拍 / 厂照；提示词＝一句话场景描述）。
   - **提供参考图**：直接作为 ImageGen 参考图输入，按产品卖点做风格 / 构图微调，不脱离原素材。
   - **提供提示词**：先按目标生图模型（当前 ImageGen）的提示词最佳实践**自主优化**——补全主体·场景·光线·构图、消除歧义、统一语种、必要时加负向词（如「无文字·无二维码」），再生成 1–3 张（1024x1024）。
   - **联系方式策略**：公开平台发布场景下，图面不嵌二维码 / 电话（防限流 / 搬运），引导用户在平台指定位自行附联系方式；点对点触达（如经客户邮箱直推）场景另行按对应分支规则处理。
4. **引导附带联系方式**：提醒用户把**自己的**联系方式（微信 / 电话 / 邮箱）放在平台允许的展示位（个人简介、评论区、置顶等），不在正文硬塞导致限流 / 删帖。

## 输出规范

- 每条线索可溯源：无来源的信息标「待验证」，不用推测冒充事实。
- 联系方式字段三态：公开公示值 / 待查（附建议查询渠道）/ 不宜采集（涉隐私）。
- 发布文案模板需注明「已按 X 平台社区条款自查：无硬广词、无绝对化用语」。

## 边界与安全

- **不采隐私**：不采集、不推测身份证号、家庭住址、私密联系方式；企业公开信息除外。
- **不做硬广**：生成的发布内容不含平台禁用的导流话术、绝对化用语（「最」「第一」）、虚假承诺，符合《广告法》。
- **不擅自代触达**：公开发布由用户自行执行；邮件直推仅在用户环境已连接 Agent Mail 时，经用户**自有邮箱**发送，环境缺失则降级为邮件草稿由用户自发送，不改用其他未授权渠道。
- **时效声明**：客户信息随时间变化，提醒用户使用前经官网 / 电话二次确认。

## Agent Mail 配置（声明 + 环境缺失引导）

邮件直推（Step 5）依赖平台原生 Connector「**Agent Mail（智能体邮箱）**」，经 `mcp__agent-mail__*` MCP 工具调用。声明如下，供运行环境按实际签名取用，本 SKILL 不自行实现接口：

| 用途 | 工具（声明） |
|---|---|
| 确认发件身份 | `mcp__agent-mail__GetMe` |
| 上传配图为附件 | `mcp__agent-mail__upload_attachment` |
| 发送至客户邮箱 | `mcp__agent-mail__SendMessage`（收件人 / 主题 / 正文 / 附件） |

**使用流程**：确认 Connector 已连接 → `GetMe` 确认身份 → `upload_attachment` 上传合成图 → `SendMessage` 发送至客户公开邮箱。

**环境缺失引导**（Connector 未连接 / 不可用）：
1. 先提示用户在 WorkBuddy Connector 面板连接「Agent Mail 智能体邮箱」，连接后即可直推。
2. 连接前降级：生成**邮件草稿**（主题 + 合规正文 + 附件说明），由用户自行在邮件客户端发送。
3. 不虚构、不猜测 MCP 参数；具体字段以运行时 Connector 暴露的 `SendMessage` 签名为准，缺失则走降级路径。
