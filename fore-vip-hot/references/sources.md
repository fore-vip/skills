# 热点素材源矩阵与检索手册

供 `fore-vip-hot` 在「候选主题快扫」与「主题深挖」两阶段使用。核心目标：在**近 3 天**窗口内，用最少检索次数拿到最高信源质量的素材。

---

## 一、信源分级（决定可信度标注）

| 等级 | 类型 | 典型来源 | 用法 |
|------|------|----------|------|
| **S** | 官方通报 / 一手发布 | 政府公告、监管部门通稿、上市公司公告、当事人官方声明、裁判文书 | 可直接作为事实陈述依据 |
| **A** | 权威媒体实名报道 | 新华社、人民日报、央视新闻、澎湃新闻、界面新闻、第一财经、财新、中国新闻网、路透/彭博中文站 | 可作为事实依据，注明媒体名 |
| **B** | 垂直/机构内容 | 36 氪、虎嗅、晚点 LatePost、少数派、雪球研究帖、券商研报摘要、GitHub Trending、arXiv 摘要 | 用于补充背景与分析，观点需标注出处 |
| **C** | 平台热榜与社交讨论 | 微博热搜、知乎热榜、今日头条热榜、抖音热榜、B 站热门、小红书、虎扑、豆瓣 | **只用于「热度与舆论」，不作为事实依据** |
| **D** | 匿名爆料 / 营销号 | 无署名自媒体、截图搬运、「据说」「内部消息」 | 默认不采信；如必须提及，显式标为「未证实传闻」 |

**判定铁律**：
- 单一 D 级来源 → 不写进正文，只在「待确认」列出并说明为何存疑。
- C 级只能支撑「网友普遍认为…」「讨论集中在…」这类**舆论描述**，不能支撑「事实是…」。
- 下「已确认」结论前，必须有 S 或 A 级来源；两个及以上独立 A/B 级来源一致且无 S 级 → 标「多方报道，暂无官方确认」。

## 二、平台矩阵（按用途分组）

### 1. 热榜聚合层 —— 用于「候选主题快扫」
适合在 Step 1 一次性扫出当天热门：

| 平台 | 检索技巧 | 说明 |
|------|----------|------|
| 微博热搜 | `微博热搜 YYYY-MM-DD`、`微博 热搜榜 今日` | 娱乐/社会向热点最灵敏，但水分高，需交叉验证 |
| 百度热搜 | `百度热搜 今日`、`百度 热点榜` | 覆盖面广，适合做候选池 |
| 今日头条热榜 | `今日头条 热榜` | 民生/社会向偏多 |
| 知乎热榜 | `知乎热榜 今日` | 适合挖科技、商业、公共议题类深度话题 |
| 抖音/快手热榜 | `抖音 热榜 今日` | 短视频流行趋势、消费类热点 |
| B 站热门 | `B站 热门 排行 本周` | 年轻向、二次元/科技/数码 |

### 2. 热榜聚合站 —— Step 1 快扫的**首选入口**（实测最高效）

与其逐个平台检索，不如先抓聚合站：**一次请求拿到 6 个平台的 Top10**。

| 站点 | 检索式 | 覆盖 |
|------|--------|------|
| 今日热榜聚合页 | `今日热榜 全网实时热点聚合` | 百度/头条/抖音/微博/知乎 各 Top10 |
| 热点源导航 | `微博 抖音 B站 虎扑 知乎 GitHub 热榜来源` | 含 IT之家、Product Hunt、GitHub Trending |
| 平台热榜合集站 | `今日热榜` / `实时热榜聚合` | 各站覆盖不同，可换着试 |

**使用方式**：`WebSearch` 拿到链接后，用 `WebFetch` 打开，一次性摘出各平台 Top10 标题作为候选池。

⚠️ **两个必踩的坑**：
1. **涉政条目占比很高**（人事任免、国防部表态、领导人行程等）。Step 1 过滤后候选常不足 6 个 → 追加定向检索补量，**不要捞回涉政项**。
2. 聚合站本身可能缓存旧数据 → 摘出的标题仍需按第三节时效闸门逐条复核日期。

### 3. 社交讨论层 —— 用于「舆论温度」
| 平台 | 检索技巧 | 说明 |
|------|----------|------|
| 微博 | `主题词 微博 讨论` + 加 `话题` | 看转发/评论量级与主流情绪 |
| 知乎 | `主题词 知乎 怎么评价` | 看深度观点与专业答主 |
| 小红书 | `主题词 小红书 笔记` | 消费/生活方式类热点的一手体感 |
| 虎扑 / 豆瓣 | `主题词 虎扑`、`主题词 豆瓣 小组` | 体育、影视、生活类舆论 |

### 4. 深度分析层 —— 用于「背景补全」
| 平台 | 检索技巧 | 说明 |
|------|----------|------|
| 36 氪 / 虎嗅 / 晚点 | `主题词 36氪 解读` | 商业科技类事件的结构化分析 |
| 微信公众号 | `主题词 公众号 复盘` | 行业纵深观点，注意署名与主体 |
| 雪球 / 研报 | `主题词 影响 券商` | 财经类事件的资金面解读 |
| GitHub Trending / arXiv | `主题词 github`、`主题词 arxiv` | 技术类热点的原始出处 |

### 5. 权威核验层 —— 用于「事实定锤」
| 平台 | 检索技巧 |
|------|----------|
| 新华社 / 人民日报 / 央视新闻 | `主题词 新华社`、`主题词 央视` |
| 澎湃 / 界面 / 第一财经 | `主题词 澎湃新闻`、`主题词 第一财经` |
| 官方渠道 | `主题词 官方 通报`、`主题词 公告` |

## 三、检索执行规范

### 时效闸门（最高优先级）
1. 所有 `WebSearch` 调用**必须带 `freshness: "d3"`**（最近 3 天）。这是「不得大于三天」的唯一技术抓手，不可省略。
2. 检索前先用 Bash 执行 `date +%Y-%m-%d` 拿到**当天真实日期**作为基准；**禁止凭记忆或推算当前日期**。
3. 每条素材都要确认发布日期：
   - 搜索结果自带日期 → 直接采用；
   - 无日期 → 用 `WebFetch` 打开原文确认；
   - 仍确认不了 → 不进主线事实，只在末尾「待确认」标注「时间未标注」。
4. 超过 3 天但属于必要背景的（例如「3 天前发布的公告，今天在发酵」）→ 允许放「背景补充」区，并**显式标注发布日期**，不与近 3 天新进展混排。

### 检索次数配额（避免无限搜索）
| 阶段 | 配额 | 说明 |
|------|------|------|
| Step 1 候选快扫 | 3–5 次 | 从不同分组各挑 1–2 个入口 |
| Step 3 主题深挖 | 8–15 次 | 覆盖 ≥4 个平台、≥3 类信源 |
| `WebFetch` 取正文 | 3–8 次 | 只对最关键、最需要定锤的 3–8 个链接 |

到达配额即停，不再追加检索；未覆盖的部分在简报末尾如实说明。

### 失败重试
- 单次 `WebSearch` 无结果或报错 → **换一个检索式重试最多 1 次**（换平台词或换同义主题词）。
- 仍失败 → 跳过该信源，继续下一个；最后在「信源清单」下方说明「本次未能覆盖 XX 平台」。
- `WebFetch` 打不开（付费墙 / 反爬 / 404）→ 标注「原文不可访问」，改用搜索摘要或换同题另一来源。

### 检索式写法
- 基础式：`<主题词> <平台名>`，例如 `OpenAI 新模型 知乎`
- 求结论：`<主题词> 怎么评价`、`如何看待`
- 求数据：`<主题词> 数据 增长 同比`
- 求官方：`<主题词> 官方 通报 声明`
- 求时间：`<主题词> 最新进展`
- 中文主题用中文检索，外文专有名词保留原文（如 `GPT-5`、`CES 2026`）。

## 四、去 AI 味的可读性规则（写作阶段强制执行）

热点简报最忌写成「AI 生成的八股文」。写作时逐条自检：

1. **禁用的套话**：首先/其次/再次/最后、综上所述、总而言之、值得注意的是、需要指出的是、在当今时代、随着……的不断发展、深耕、赋能、抓手、闭环。
2. **禁用的结构**：三段式机械排比、每段都以「此外」「另外」开头、通篇等长段落。
3. **标题要有信息**：写「苹果宣布 9 月 10 日发布 iPhone 17」，不写「深度解析：iPhone 17 发布会前瞻」。
4. **长短句交错**：长句交代背景，短句下判断。别全是一个模板。
5. **数据要有锚点**：写「涨了 47%，相当于去年全年增量的两倍」，不孤立甩数字。
6. **emoji 克制**：全文最多 3–5 个，只用于区块标题，不做行内装饰、不做列表符号。
7. **不造金句**：宁可平实，不要「这不仅是……更是……」式的强行升华。
8. **观点要署名**：「 analysts 认为」→「中金在 8 月 28 日研报中认为」。

## 五、合规红线（一票否决）

- **涉政、军事、民族宗教、领土主权类话题一律不做**：候选主题生成阶段即过滤；用户主动输入时，说明原因并请换一个主题。
- **不造谣不传谣**：无来源的信息宁可不写；宁可说「暂未检索到可靠信息」。
- **违法犯罪、未成年人相关**：只引用官方通报原文，不猜测细节、不描述手法。
- **不挖隐私**：不检索当事人住址、家属、私人联系方式等非公开信息。
- **投资/医疗/法律**：只做信息整理与风险提示，不给具体操作指令（不荐股、不诊断、不下法律结论），并附免责声明。
