# 信源分级与取证纪律

> 来源：`_common/references/source-grading.md @ 1.0.0`
> 用于调研、检索、评分与结论评审。

## 一、四路定位

| 信源 | 作用 | 可信度 | 纪律 |
|---|---|---|---|
| 模型基础档案 | 规模、性质、成立时间、主营、基础背景 | 参考级 | 必须标注「模型侧信息，未外部核实」，不作评分证据 |
| 社区与口碑 | 真实体验、工时、服务、争议线索 | 中 | 单条不算数，同类独立来源 ≥3 条才认定为模式 |
| 搜索引擎 | 发现线索、补充缺口 | 中 | 结论要回到原始来源核实 |
| 资讯站与原始文书 | 裁判文书、处罚决定、公告、披露、行业调查 | 高 | 优先采信，注意结论与理由 |

取证顺序：先定范围 → 查硬性合规（可能直接改变结论）→ 查体验与口碑 → 补缺口。先查硬信息可避免在明显有问题的对象上浪费检索预算。

## 二、ABCD 分级

| 等级 | 来源 | 用法 |
|---|---|---|
| A 已证实 | 生效文书、政府决定、官方公示、企业公告 | 可直接作为结论依据 |
| B 可核验 | 权威媒体调查、公开披露、第三方审计报告 | 可用，注明媒体名与日期，降一档力度 |
| C 待核实 | 单方爆料、匿名帖、平台抱怨、投诉个案 | 标「未证实」，限制使用力度 |
| D 不可用 | 无信源传闻、生成内容、营销号拼凑、竞品抹黑 | 不采用 |

辨认 D 级：无具体时间地点、无当事人身份、多平台同文案复制、通篇情绪无细节。水军好评特征：短时间集中出现、句式雷同、无具体经历。

## 三、检索式模板

按「**主体名 + 关键词**」组合，用引号锁定主体名避免歧义：

```
"{主体}" {核心指标}
"{主体}" {争议点}
"{主体}" {时间口径} 公示
site:{权威站点} "{主体}" {案由}
```

按维度分组跑，每组保留可点开的路径；站点限定在各平台支持 `site:` 时才用。检索结果按时效闸门过滤，优先近 3 年。

## 四、取证六条

1. **记三样**：来源名称 + 可点开链接或可复现路径 + 时间。缺一样不算证据。
2. **看清主体**：品牌名不等于工商主体名；集团要区分母子公司，连锁要区分加盟与总部。
3. **区分主张与结论**：立案不等于判决，起诉不等于过错，需看到结果与理由。
4. **看时间衰减**：多年前的问题若已整改，只作背景，不重复计入当次结论。
5. **诚实留白**：查不到写「未检索到公开信息」，这是有效结论；查不到是「未知」，不是「清白」。
6. **不做人情分**：自己用过、用户已买、偏好品牌都不加减分。

## 五、信息不足的处理

| 情形 | 处理 |
|---|---|
| 子项缺失 | 记 `null`，按行业中位代入并标「信息不足·按中位代入」，同时算数据完整度 |
| 完整度 < 50% | 不进确定排名，单列「无法可靠评估」区，并写清缺什么、怎么补 |
| 结论口径 | 限定在「本次候选范围内」，不外推为行业结论 |
| 事实性判断 | 出现「最 / 首 / 唯一 / 第一」等表述时，回原始证据重算，不沿用转述 |

## 六、取数可靠性（工程注意）

- 站点限流会伪装成空白页：状态码 200 但返回体极小，或连接层报空；对返回体大小做合理性断言，异常则慢速重取。
- 判断「页面不存在」前，先请求一个确定不存在的路径取对照，再下结论。
- 正文直取被拒时走检索索引，并注明「经检索索引取得（直取被拒）」。
- 用 `WebSearch` / `WebFetch` 现场取数，不凭记忆编 URL。

## 七、交付要求

每条关键结论标注来源、时间与适用范围。信源清单逐条列出；标注「未证实」的条目注明属单方主张，未经司法或行政确认。
