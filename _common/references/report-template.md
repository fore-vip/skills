# 报告结构与措辞

> 来源：`_common/references/report-template.md @ 1.0.0`
> 用于调研报告、评审结论、交付汇报。结论先行，表格优先于段落。

## 一、六段式结构

| 序 | 板块 | 硬要求 |
|---|---|---|
| 1 | 结论 | 一行给关键判断或建议，先说结果 |
| 2 | 需求与范围 | 复述目标、口径、时间窗、适用范围 |
| 3 | 证据 | 表格逐条列事实：来源、日期、等级、适用范围 |
| 4 | 分析 | 推导链条与假设，和事实分开写 |
| 5 | 建议 | 触发条件、代价、未决项与补验方式 |
| 6 | 信源清单与免责 | 来源与日期齐全，说明结论局限 |

不自由发挥成散文。每份报告落到「所以该怎么做」，不产出无人使用的信息表。

## 二、措辞对照

| 不要写成 | 改写成 |
|---|---|
| 没有 / 不存在 | 本次检索未发现公开记录 |
| 第一 / 行业领先 | 本次候选范围内排名第一（附口径） |
| 保证 / 一定 | 在 X 条件下，证据显示为 Y |
| 违法 / 造假（未定性） | 公开信息显示存在争议（附文书） |
| 显然 / 必然 | 由 A、B 两条推导，假设是 C |
| 已完成（未验证） | 本地已生成，线上未验证 |

「未发现」与「没有」是两回事，报告里写前者。禁用绝对化用语与承诺效果表述，见 `compliance.md`。

## 三、数据不足时的改写

```
## 无法可靠评估

| 对象 | 数据完整度 | 缺什么 | 补验方式 |
|---|---|---|---|
| {对象} | {n}/{总数} | {缺失维度} | {具体渠道或动作} |

> 注：{对象} 因公开证据不足，本次不作排名。
```

放在证据表之后、结论之前，并在结论开头加一句说明，避免给出不可靠的确定结论。

## 四、HTML 版报告

| 约束 | 口径 |
|---|---|
| 底色 | 浅色底 + 深色文字，跟随当前主题；不默认深色 |
| 资源 | 自包含，不引外部字体、图片、脚本，离线可开 |
| 图表 | 涨红跌绿（中国习惯），金额默认 `¥` |
| 结构 | 头部指标 → 明细表 → 结论 → 页脚免责 |
| 动效 | 存在动效时，在 `prefers-reduced-motion` 下关闭 |

## 五、汇报口径

- 写清产出文件、改动范围、验收证据、未做事项与风险。
- 示例数据写示例数据，未上线写未上线，未验证写未验证。
- 命令执行、数据核对、诊断类任务：把关键输出行或数字直接写进汇报，不依赖折叠的过程记录。
- 事实 / 分析 / 建议三层分开；不确定处用「基于当前数据」「证据表明」作限定。

## 六、免责

报告结论基于公开可检索信息在给定范围内的横向比较，不构成法律、医疗、投资或资质认定；状态随时间变化，以最新公开信息为准。
