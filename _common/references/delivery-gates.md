# 交付、发布与提交闸门

> 来源：`_common/references/delivery-gates.md @ 1.0.0`
> 用于改动收尾、提交前复核、上线判定。

## 一、协作链（不可省）

```
改 → 自测 → commit + push → 线上复核 → 汇报
```

不问「要不要 push」。**必须先问的四类例外**：删除或破坏性操作、跨库跨端影响面不确定、提交边界含他人改动、需求本身有歧义。

## 二、按仓库的发布闸门

| 单元 | 触发 | 闸门 |
|---|---|---|
| Web 前端（托管型） | 改页面资源 | 必须重建产物并上传；`commit + push` 不影响线上 |
| 双端应用 | 改公共层、组件、服务端对象、表结构 | 两端各验一遍 |
| 静态站点 | 页面增删改 | 站点地图同步 + 断链检查两道 fail-closed，再执行发布；新页面先追加进校验清单 |
| 技能仓库 | 发布技能包 | 先跑仓库校验，再走发布；新增技能同步改目录、清单数组、白名单三处 |
| 文档 | 改中英 README | 两份结构一致（标题 / 代码块 / 表格行 / 分隔线计数） |
| 回归 | 改前端或服务端对象 | 跑仓库级回归套件 |

禁止手写站点地图；禁止用同步删除方式清理远端目录。

## 三、提交纪律

| 规则 | 做法 |
|---|---|
| 只暂存自己的改动 | 工作树里有别人的活时，`git diff <f>` 存 patch → 按标记筛掉别的工作的 hunk → `git apply --cached`；别用 `git add` 整文件裹带半成品 |
| 版本号 | 跟随目标仓库惯例，提交信息带版本与一句说明 |
| 行尾符 | 改已知 CRLF 文件后立刻 `git diff --numstat` 核对；数量级接近总行数即整篇被改写 |
| 高频改动文件 | 动之前先看 `git log`，可能存在并行提交 |
| 提交边界 | 只提交本轮目标文件，不顺手夹带无关修复 |

## 四、自检纪律

1. **断言里的数字现算**：计数先扫再写，不拍脑袋。
2. **运算符优先级**：负向断言一律加括号，避免吞掉整条检查。
3. **断言口径复核**：每轮「有意改变」回头审一遍钉旧口径的断言。
4. **行尾符探测**：改文件前先探行尾符，文本模式读会吞 CRLF。
5. **反向对照前备份**：备份全部受影响文件，不只备要替换的那几个。
6. **错误文案固定化**：服务端 5xx 固定文案，原始错误只进日志；前端不透传原始 message。

## 五、平台交互红线

- 平台确认框被用户取消 → 停，不重试、不绕路、不静默降级。
- 未拿到环境确认就别写依赖该环境的代码。
- 发布需用户明确指令；`commit + push` 不等于已上线。
- 交付说明写清是本地预览还是已上线，附验收证据与未做事项。

## 六、收尾清单

1. 本轮改动文件清单与验收结果。
2. 闸门执行结果（逐条 PASS / FAIL）。
3. 版本号与提交号。
4. 未做事项、已知风险、下一步触发条件。
5. 关键实施步骤回写项目记忆，供后续会话复用。
